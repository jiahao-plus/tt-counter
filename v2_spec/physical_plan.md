## 1. 面积预算（实测 + 外推，明确标注）

### 1.1 V1 实测基线

从 V1 routed DEF 直接解析（`macros/area_budget.py`）：

| 项 | 值 |
|---|---|
| Die | 161.000 × 111.520 µm = 17 955 µm² |
| **Core**（ROW 覆盖范围） | 155.480 × 103.360 µm = **16 070 µm²** |
| 行数 | 39 |
| 每行列数 | 338（STEP 0.460 µm） |
| **Cell sites** | **13 182** |
| 行高 | 2.720 µm |
| 边距（L/B/R/T） | 2.76 / 2.72 / 2.76 / 5.44 µm |

### 1.2 2×2 外推（**上界，非实测**）

沿用 V1 边距，套到 335 × 226 µm：

| 项 | 值 | 倍率 |
|---|---|---|
| Nominal | 335 × 226 = 75 710 µm² | 4.22× |
| **Core** | **71 774 µm²** | **4.47×** |
| 行数 | 80 | 2.05× |
| 每行列数 | 716 | 2.12× |
| **Cell sites** | **57 280** | **4.35×** |

> ⚠️ **这是外推，不是实测**。本地无 `tt_block_2x2_pg.def`，2×2 的 PDN
> 边距可能与 1×1 不同（左右边距可能更大，因为要容纳 cross-tile 电源）。
> **必须以首次官方 CI 的 DEF 为准**。

### 1.3 研究结构面积占用估算

| 结构 | 单实例尺寸 (µm) | 面积 (µm²) | 计划实例数 | 小计 (µm²) |
|---|---|---|---|---|
| A research_via1 | 8.14 × 4.94 | 40.2 | 8 | 322 |
| B research_via2 | 10.22 × 3.24 | 33.1 | 8 | 265 |
| C1 research_branch | 10.14 × 3.20 | 32.4 | 4 | 130 |
| C3 research_near | 10.14 × 8.24 | 83.6 | 4 | 334 |
| C4 research_cross | 10.14 × 8.14 | 82.5 | 4 | 330 |
| D research_dense | 35.00 × 5.79 | 202.7 | 2 | 405 |
| E research_fiducial | 4.00 × 4.00 | 16.0 | 6 | 96 |
| **合计** | | | **36** | **≈ 1 882** |

**占比：1 882 / 71 774 = 2.6%**。即使加上布线开销和禁布区，研究结构
占用的面积远小于可用面积——**面积不是约束**。

真正约束是：
1. **宏放置位置**必须避让 PDN strap 和标准单元行
2. **宏的 PIN 必须能被布线器接上**（否则成为孤岛）

## 3. 宏集成方式

### 3.1 命名一致性要求（任务书 §4.3）

| 项 | 值 |
|---|---|
| GDS cell 名 | `research_via1` 等 |
| LEF MACRO 名 | 同上 |
| Verilog 模块名 | 同上（黑盒或行为模型） |
| 实例名 | 由布线器生成 |

**当前状态**：GDS cell 名与 LEF MACRO 名已一致（`macro_index.json` 可验证）。

### 3.2 config.json MACROS 配置

V1 使用的是 Tiny Tapeout 官方 `src/config.json`（LibreLane 风格）。V2 需加入：

```json
"MACROS": {
  "research_via1": {
    "gds": ["dir::../macros/out/struct_A.gds"],
    "lef": ["dir::../macros/out/struct_A.lef"],
    "instances": {
      "u_via1_0": { "location": [10, 20], "orientation": "N" }
    }
  }
}
```

> ⚠️ **未经官方 CI 验证**。LibreLane 的 MACROS 语法需以官方模板为准，
> 不能照搬旧版 OpenLane 语法。

### 3.3 放置约束

| 约束 | 说明 |
|---|---|
| 必须避开 PDN strap | M4 strap 在 V1 为 x = 19.08/22.38/57.95/61.25/96.82/100.12/135.69/138.99；2×2 会不同 |
| 必须落在 core 区域内 | 外推 core 为 x 2.76..332.24, y 2.72..220.56 |
| 必须对齐行网格 | 行高 2.72 µm，x 步长 0.46 µm |
| PIN 必须可布线 | 结构 PIN 在 M1/M2/M3 上，需能被 met1-met4 布线器接入 |

### 4.2 删减计划

**当前无删减**。V1 的逻辑面积仅 2 977.86 µm²（综合）/ 16 493 µm²（实例含 fill），
在 71 774 µm² 的 2×2 中占比极小。研究结构只需 1 882 µm²。

> 若后续发现面积不足（例如 PDN 占位比预期大），优先删减：
> 1. 冗余的 buffer/inverter（55 个中可减）
> 2. 时序修复用的 dlygate（53 个）
> **不删减** Counter/PWM/LFSR 的核心逻辑。

### 4.3 严禁

- ❌ SERV / PicoRV32 / 任何 CPU
- ❌ 修改 V1 的任何文件
- ❌ 扩大 tile

## 7. 已知风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 2×2 core 实际比外推小 | 面积预算失真 | 首次 CI 后重算 |
| MACROS 语法不被 LibreLane 接受 | 宏无法集成 | 先查官方模板；必要时改用 GDS 合并 |
| 宏 PIN 无法被布线器接入 | 结构成孤岛 | 在 macro 边界留足 landing |
| 结构被 fill 覆盖 | SEM 无法成像 | 在宏周围设 keepout |
| 2×2 布不通 | 整个 V2 失败 | 首次 CI 即验证；失败则回退 1×1 或减少结构 |
